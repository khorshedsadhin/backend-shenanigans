Module এর চারটা array

Arrayকোন প্রশ্নের উত্তরসাবধান
imports অন্য কোন module আমার লাগবে? শুধু module নেয়, কখনো provider না।
controllers এখানে কোন class HTTP ধরে? Controller কখনো providers এ যায় না, export ও হয় না।
providers কী আমার নিজের, ভেতরে inject হয়? Register এখানেই হয় — শুধু @Injectable() দিয়ে কিছু হয় না।
exports যারা আমাকে import করে, তাদের কী ধার দিই? providers এও থাকতে হবে। এটা বাদ পড়াই cross-module bug নম্বর ১।
একটাই নিয়ম

Provider তার module এর private, export না করা পর্যন্ত। Share করতে দুটোই লাগে: মালিক exports করে, যে চায় সে মালিক module কে imports করে।

Standard shape

Service (provider)

import { Injectable } from '@nestjs/common';

@Injectable()
export class UsersService {
  constructor(
    private readonly db: Database,
  ) {}

  findAll() { return []; }
}

Controller

import { Controller, Get, Param }
  from '@nestjs/common';

@Controller('users')
export class UsersController {
  constructor(
    private readonly svc: UsersService,
  ) {}

  @Get()
  findAll() { return this.svc.findAll(); }

  @Get(':id')
  one(@Param('id') id: string) { return id; }
}

Service private রাখে এমন module

@Module({
  controllers: [UsersController],
  providers:   [UsersService],
})
export class UsersModule {}

Service share করে এমন module

@Module({
  controllers: [UsersController],
  providers:   [UsersService],
  exports:     [UsersService],   // ধার দাও
})
export class UsersModule {}

@Module({
  imports:   [UsersModule],      // ধার নাও
  providers: [OrdersService],
})
export class OrdersModule {}

Injection scope

Scopeকয়টা instanceকখন ব্যবহার
DEFAULT একটা, পুরো app share করে, app যতক্ষণ চলে। প্রায় সবসময়। Service কে stateless হতে হবে। এটাই default; লিখতে হয় না।
REQUEST প্রতিটা request এ একটা, তারপর garbage collect। Provider এ সত্যিই per-request state লাগলে (যেমন multi-tenant context)। Latency বাড়ায়, আর scope টা উপরে ছড়িয়ে পড়ে — যারা এটা inject করে, তারাও REQUEST হয়ে যায়।
TRANSIENT যে inject করে, প্রত্যেকে নিজের নতুন instance পায়। কদাচিৎ। সাধারণত logger, যার জানা দরকার কে তাকে inject করেছে।
 
@Injectable({ scope: Scope.REQUEST })
export class TenantContext {}

Docs → Injection Scopes। Default scope singleton, তাই provider এর field এ কখনো per-request state রেখো না।

Error decoder

MessageমানেFix
Nest can't resolve dependencies of the X (?). ... argument Y at index [0] is available in the Z context Nest X বানাতে গিয়ে Y চেয়েছে, কিন্তু module Z এ কোনো registered Y পায়নি। Y কে Z এর providers এ দাও — অথবা Y অন্য module এর হলে সেখানে export করো আর ওই module কে Z তে import করো।
... argument at index [0] is available in the ... context কিন্তু argument এর নাম Object বা undefined দেখায় Type metadata তৈরিই হয়নি, সাধারণত দুইটা file একে অপরকে import করছে (circular import)। Cycle ভাঙো, অথবা শেষ উপায় হিসেবে দুই দিকেই forwardRef(() => OtherModule)।
ঠিকঠাক চালু হয়, কিন্তু shared cache বা counter উল্টাপাল্টা আচরণ করে। Provider দুইটা module এর providers এ লেখা, তাই দুইটা instance। ঠিক একটা module এ declare করো, export করো, আর বাকি সব জায়গায় সেই module import করো।
এক user আরেক user এর data দেখে, শুধু load এর সময়। Singleton provider এর field এ per-request state রাখা। State বাইরে সরাও: method argument হিসেবে পাঠাও, অথবা database বা cache এ রাখো।

CLI, মুখস্থ রাখার মতো

nest new <app>                # project বানাও
nest g module users           # module (AppModule এ নিজে import হয়)
nest g controller users       # controller (UsersModule এ নিজে register হয়)
nest g service users          # provider  (UsersModule এ নিজে register হয়)
nest g resource users         # উপরের সব + CRUD + DTO
npm run start:dev             # watch mode
এটা সাথে রাখো
