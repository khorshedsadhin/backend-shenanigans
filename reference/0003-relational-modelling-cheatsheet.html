Relational Modelling

Mongo থেকে Postgres এ অনুবাদ, type, constraint, আর error — এক page এ।

Mongo → Postgres অনুবাদ

Mongo তেPostgres একেন
_id id bigint generated always as identity primary key Auto-increment এর Postgres রূপ। UUID ও চলে, তখন uuid + default gen_random_uuid()।
Embedded object — user: { name, email } আলাদা users table + user_id foreign key Fact টা এক জায়গায় থাকে, তাই email বদলালে এক row বদলায়।
Array of subdocuments — items: [ {...} ] Child table, যার একটা FK parent এর দিকে "Many" দিক থেকে আঙুল ওঠে। এক parent এ কতগুলো child, সেটা আগে জানার দরকার পড়ে না।
Array of ids বা strings — tags: [ ... ] Join table — post_tags(post_id, tag_id) Many-to-many। Array column এ foreign key খাটে না, তাই ওটা ছদ্মবেশে Mongo অভ্যাস।
Field এ আজ string, কাল number Column এর একটা declared type, database নিজে জোর করে ভুল data insert এর সময়ই আটকায়, ছয় মাস পর production এ না।
ref কিন্তু পাহারা নেই references users(id) Orphan row ঢুকতেই পারে না — application এ if লেখার দরকার নেই।

Column type, এখনকার জন্য

Typeকীসের জন্যফাঁদ
textনাম, email, যেকোনো string varchar(n) দ্রুত না। Limit দাও শুধু সত্যিকারের business নিয়ম থাকলে।
bigintid, count integer ২১৪ কোটিতে শেষ। Id এ কখনো risk নিও না।
numeric(10,2)টাকা, দাম টাকার জন্য float/double কখনো না — rounding এ টাকা হারায়।
timestamptzকখন ঘটলো timestamp timezone ফেলে দেয়। সবসময় tz ওয়ালাটা।
booleanহ্যাঁ/না null ও একটা সম্ভাবনা — দরকার না হলে not null default false।
uuidবাইরে দেখানো id Sequence থেকে row গোনা আটকায়, কিন্তু index এ বড় আর random।

Constraint syntax

-- এক column এর primary key
id bigint generated always as identity
   primary key

-- একটাই থাকবে, খালিও না
email text not null unique

-- অন্য table এর দিকে আঙুল
user_id bigint not null
  references users(id)
-- value র উপরে নিয়ম
quantity integer not null
  check (quantity > 0)

-- দুই column মিলে primary key
primary key (order_id, product_id)

-- পরে যোগ করা
alter table orders add constraint
  orders_user_fk foreign key (user_id)
  references users(id);

Docs → Constraints। মনে রাখো: unique, not null আর references তিনটা আলাদা পাহারাদার, একজনের কাজ আরেকজন করে না।

সম্পর্ক → কী বানাবে

সম্পর্কউদাহরণযা বানাতে হবে
One-to-oneuser ↔ profile Child table এ FK, আর সেই FK তে unique। বা একই table এ রেখে দাও।
One-to-manyuser → orders "Many" দিকে FK: orders.user_id। Parent এ কিছু যোগ হয় না।
Many-to-manyorders ↔ products Join table, দুইটা FK, আর দুইটা মিলে composite primary key।
সম্পর্কের নিজের factএই order এ এই product কতটা Join table এর column (quantity) — কোনো পাশে না।

Error decoder

MessageমানেFix
insert or update on table "orders" violates foreign key constraint "orders_user_id_fkey" যে user_id দিয়েছ সেটা users এ নেই। Orphan row বানানোর চেষ্টা। আগে user টা insert করো, তার আসল id নিয়ে তারপর order।
update or delete on table "users" violates foreign key constraint ... on table "orders" উল্টো দিক: এই user কে কেউ এখনো দেখাচ্ছে, তাই মুছতে দিচ্ছে না। আগে order গুলো সরাও, অথবা FK তে on delete নিয়ম ঠিক করো (পরের lesson)।
duplicate key value violates unique constraint "users_email_key" এই email আরেকটা row এ আছে। unique আটকেছে। আসল duplicate হলে data ঠিক করো। নিয়মটাই ভুল হলে constraint বদলাও, লুকাও না।
new row for relation "order_items" violates check constraint "order_items_quantity_check" Value টা check (...) এর শর্ত মানেনি — যেমন quantity = 0। Value ঠিক করো। Check টা কাজ করেছে, এটাই তো চাওয়া ছিল।
null value in column "email" of relation "users" violates not-null constraint Column বাদ দিয়েছ আর তার কোনো default নেই। Value দাও, অথবা column এ যুক্তি থাকলে default দাও।
কিছুই হচ্ছে না, psql শুধু scalelab-# দেখাচ্ছে Statement শেষ হয়নি — semicolon দাওনি, বা quote/bracket খোলা। ; দাও। আটকে গেলে \r দিয়ে লাইনটা বাতিল করো।

Docker আর psql, মুখস্থ রাখার মতো

docker start scale-pg                              # container চালু
docker exec -it scale-pg psql -U postgres -d scalelab  # ভেতরে ঢোকা
docker logs --tail 20 scale-pg                     # চালু না হলে এখানে কারণ

একটা fact এক জায়গায় ⇒ copy নেই ⇒ update anomaly নেই ⇒ দাম হলো join ⇒ join ধীর হলে index। এই শিকলটাই roadmap এর step 2 → 4 → 7। Schema ভুল হলে শিকলের প্রথম কড়াই ভাঙা, আর index দিয়ে সেটা জোড়া লাগে না। দেখো MISSION.md।
